## 1. 문서 목적

본 문서는 **과외 선생님(담당자)** 이 학생·수업 일정·진도·주간 리포트를 관리하기 위한 시스템의 **기능 요구사항**을 정의한다. 구현·테스트·검수 시 「무엇을 제공해야 하는가」의 기준으로 사용한다.

**기술 구현 상세**는 [시스템 사양서.md](./시스템%20사양서.md) 및 도메인별 명세 문서를 따른다.

## 2. 시스템 개요

### 2.1 목적

- 다수 학생의 **정규 수업 패턴**을 등록하고, 실제 수업(`Lesson`)을 **제안·승인·완료·취소**하며 홈 **달력**에서 한눈에 파악한다.
- 학생별 **진도·메모·이력**을 기록하고, **주간 수업 현황**으로 완료·취소 수업을 집계한다.
- **웹 브라우저**와 **Android 앱**에서 동일 데이터에 접근한다(앱은 1차 MVP 범위 제한).

### 2.2 사용자

| 역할 | 설명 |
|------|------|
| **담당자(Tutor)** | 회원가입한 과외 선생님. 본인이 등록한 학생·수업만 조회·편집 |
| **시스템 관리자** | 별도 역할 없음(1차). 인프라·DB는 운영자가 호스트에서 관리 |

### 2.3 클라이언트

| 클라이언트 | 1차 범위 |
|------------|----------|
| **웹** | 전 기능(명세 확정 범위) |
| **Android** | 로그인, 학생 조회, 달력(조회·완료), 주간 현황 — [mobile-android.md](./mobile-android.md) |

### 2.4 용어

| 용어 | 정의 |
|------|------|
| 담당자 | 로그인한 `User`. `Student.owner` |
| 정규 수업 | `ScheduleSlot` — 요일·시간 반복 템플릿 |
| 제안 | 슬롯·날짜에 맞춰 계산된 **가상** 일정. DB `Lesson` 없음 |
| 수업(`Lesson`) | 실제 1회 수업 인스턴스 |
| 회차 | `lesson_number`. 생성 시 `lessons_completed + 1` 고정 |
| 완료 회차 | `Student.lessons_completed` — 완료 수업 누적(수동 입력·완료 시 증가) |

## 3. 기능 요구사항

요구 ID 형식: `FR-{영역}-{번호}`. 우선순위: **M**(Must), **S**(Should), **C**(Could), **X**(1차 제외·추후).

### 3.1 계정·인증 (ACC)

| ID | 우선순위 | 요구사항 | 비고 |
|----|----------|----------|------|
| FR-ACC-01 | M | 이메일·비밀번호로 **공개 회원가입**할 수 있어야 한다 | |
| FR-ACC-02 | M | 가입 후 **이메일 인증**을 완료해야 로그인할 수 있어야 한다 | |
| FR-ACC-03 | M | 로그인 식별자는 **이메일만** 사용해야 한다 | |
| FR-ACC-04 | M | **Google, GitHub, 네이버** 소셜 로그인을 지원해야 한다(웹) | |
| FR-ACC-05 | M | 로그인하지 않은 사용자는 학생·수업 기능에 접근할 수 없어야 한다 | |
| FR-ACC-06 | M | 로그인 성공 시 **홈 달력**으로 이동해야 한다 | |
| FR-ACC-07 | S | 로그인 실패가 반복되면 계정을 일시 잠금해야 한다 | django-axes |
| FR-ACC-08 | S | 비밀번호 변경 등 **민감 작업** 전 TOTP 재인증을 요구해야 한다 | WebAuthn은 추후 |
| FR-ACC-09 | M | Android 앱은 **이메일·비밀번호**로 로그인해야 한다 | JWT 발급 |
| FR-ACC-10 | X | Android에서 소셜 로그인 | 2차 |
| FR-ACC-11 | X | Android 가입 UI | 웹 가입 안내 |

*상세: [auth.md](./auth.md), [api.md](./api.md)*
